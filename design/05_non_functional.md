| 項目 | 内容 |

機能では表せない品質特性を記述する。数値は「**基準環境＋目安値**」方式（基準を満たす環境での目標。厳密なSLAではなく実装/検証の指針）。

**基準環境**：4コア/8GB RAM の一般的なサーバまたは開発PC、SSD、ローカル or LAN 接続のブラウザ（Chrome/Edge 最新）。単一組織・少人数（同時接続 〜20 セッション想定）。

## 1. 性能

| 項目 | 目標値（目安） |
|---|---|
| 画面初期表示（SSR、キャッシュ後） | 1.0 秒以内 |
| 一覧取得・ページ切替 | 300ms 以内（1ページ 50〜100 件） |
| 作成/更新/削除の応答 | 500ms 以内（監査記録込み） |
| 統合ダッシュボード全ドメイン集計 | 2.0 秒以内（部分失敗は個別表示） |
| ダッシュボード自動更新間隔 | 既定 30 秒（`policy.dashboard_refresh_secs` で 5〜3600 可変） |
| 想定データ規模（快適動作） | ドメインあたり主エンティティ 〜100,000 件（DNSレコード/LDAPエントリ/リース等）をページング前提で操作可能 |
| 監査ログ蓄積 | 100万件規模でもフィルタ検索が実用速度（インデックス前提） |
| WASM バンドル | サイズ最適化（`opt-level="z"`, lto）で初回転送を抑制 |

## 2. 対応環境

| 項目 | 内容 |
|---|---|
| 配布形態 | **単一バイナリ**（`magnetite-server` ＋設定ファイル）。プロセス分離なし |
| 対応OS（サーバ） | Windows / Linux（x86_64）。SurrealDB(rocksdb)ビルドに LLVM/libclang |
| 対応ブラウザ | Chrome / Edge / Firefox 最新。SSR により低速端末でも初期表示可能 |
| 最小画面幅 | 768px（管理コンソール想定）。狭幅はサイドバー折りたたみ＋主要列表示（S-00 §7） |
| 必要ランタイム | 外部DBサーバ不要（組込みDB）。SSO は任意（未設定でもローカル認証で稼働） |
| 言語 | 日本語／英語（i18n、日本語を正） |

## 3. ユーザビリティ／アクセシビリティ

- キーボードのみで主要操作が完結（`/`検索・`n`新規・`Esc`閉、テーブル行移動、Enter送信：S-00 §4/§7）。
- フォーカス順序が論理的で、ダイアログ表示時にフォーカスを移し `Esc` で閉じられる。
- コントラスト比は **WCAG AA 相当**を満たす。状態表示は**色＋テキスト/アイコン**（色覚非依存。例：状態バッジ）。
- すべての操作に視覚的フィードバック（押下・スピナー・トースト）を返す。
- ダーク／ライトの両テーマでコントラスト基準を満たす。

## 4. 信頼性・エラー処理方針

- 想定エラー（通信/処理失敗・入力不正・データ不整合・権限不足）には**専用の表示と復帰手段**（再試行/確定文言/非活性）を用意（各画面 §3 状態、04 AC の文言）。
- ダッシュボード等の集約画面は**部分失敗を許容**し、失敗ドメインのみ再試行できる（AC-06）。
- 予期しないエラーでもアプリはクラッシュせず安全に復帰（パニックフック＋ログ、移行元踏襲）。
- 破壊的操作（削除/リストア/制御）は確認ダイアログ＋監査記録を必須とする。
- モノリス化により旧「プロセス異常検知・自動再起動」は**内部モジュールの障害隔離**へ再定義（意味論は 09）。

## 5. セキュリティ

- 認証は統一（ローカル：Argon2 ／ SSO：OIDC/PKCE）。**サービス個別トークンをブラウザに露出させない**（SSR＋サーバ側処理を継続）。
- 認可は統一 RBAC（Viewer/Operator/Admin）。参照系＝認証必須、更新系＝Operator 以上、破壊/制御/設定/アカウント＝Admin。
- パスワードポリシー：8文字以上・英数字含む（`policy` で管理。AC-03）。
- 機微情報（SSO secret 等）はマスク表示し、監査ログに値を残さない。
- 監査ログは**追記のみ・改変不可**。全更新系操作を記録（記録率 100%、成功指標）。
- セッションは Cookie（HttpOnly 等）で管理。失効操作で即時無効化（AC-05／意味論 09）。
- 連続ログイン失敗時の遅延/ロックは実装フェーズで方針化（残課題、S-Login §7）。

## 6. 保守性

- 設定は外部ファイル（`portal.toml` 相当＝`AppConfig`）に外部化し、**ホットリロード**可能（F-09／09）。
- 仕様が受け入れ基準（04 AC, Given/When/Then）としてE2Eの根拠になる（テスト容易性）。
- ドメインは内部モジュールとして分離し、共有構造（07 §3）で横断関心事を一元化（重複削減）。
- 運用ログ（LogEntry）と監査ログ（AuditEntry）を分離。保持期間は `policy.retention_days` で設定。
- i18n はキー管理（ja/en）で文言を一元化。

## 7. 制約

- 実装は Rust / Leptos 0.8（SSR+WASM hydrate）/ Axum 0.8 / SurrealDB 3 を基本（移行元踏襲。詳細は実装フェーズ）。
- 単一組織・単一デプロイ前提（マルチテナント非対応）。
- 依存の一部（rocksdb 等）は C/C++ ツールチェイン（LLVM）を要する。

## 8. 保持・容量の既定（`policy`／設定で調整）

| 対象 | 既定 | 備考 |
|---|---|---|
| 監査ログ保持 | 90 日 | `retention_days`。超過は古い順に削除（追記不変の範囲で世代管理） |
| 運用ログ（LogEntry） | 直近 N 件/期間 | ドメイン別。リングバッファ相当の上限（実装で確定） |
| バックアップ世代 | 手動=無制限（手動削除）／自動=世代数上限 | 自動世代数は設定（F-06/09） |
