## 1. 目的・背景

**Magnetite** は、社内インフラを構成する 8 つのサービス（SSO / LDAP / DNS / DHCP / Mail / Proxy / コンテナ・K8s / 監視）を、**単一の統合アプリケーション**として提供し、Web インターフェース・UI/UX・認証を統一した一元管理ツールである。

### 背景（現行の課題）

現行版（`service-integration`）は、8 サービスがそれぞれ独立プロセス（git サブモジュール）として稼働し、その上位に「ポータル」が API ゲートウェイで中継する構成であった。この構成は次の課題を抱える。

- **運用の複雑さ**：8 プロセスの起動・停止・ヘルス・再起動を個別管理する必要がある。
- **認証の分断**：サービスごとに認証方式が異なり（JWT / セッション / API キー / なし）、トークン中継の複雑さと一貫性の欠如がある。
- **UI/UX の不統一**：サービス由来の画面パターンがばらつき、操作学習コストが高い。
- **機能の重複**：ユーザ/グループ管理・監査ログ・アラート・バックアップ・テンプレート等が各サービスに散在する。

### 本再設計で解決すること

- 8 サービスのコアロジックを**アプリ内部モジュール**として取り込み、**単一バイナリ・単一プロセス**で提供する（プロセス分離・API ゲートウェイ・プロセスマネージャを廃止）。
- 認証を**統一（ローカル＋SSO の2経路、統一 RBAC）**する。
- 重複機能を**横断共通機能へ統合**し、UI/UX を標準化する。

## 2. ターゲットユーザー

| ペルソナ | 説明 | 主な利用シーン |
|---|---|---|
| 社内インフラ管理者（情シス/社内IT） | 単一組織のインフラを 1 人〜少人数で運用する管理者。ネットワーク・ディレクトリ・メール・コンテナ等を横断的に扱う。 | 日常の設定変更・障害対応・監視確認を、1 つの画面から実施 |
| 一次対応オペレータ | 参照と定型操作（アラート確認・リース解放等）を担う運用担当。 | アラート対応、状態確認、限定的な更新操作 |
| 監査担当（任意） | 操作履歴・変更履歴を確認する担当。 | 監査ログ・変更履歴の閲覧 |

> **スコープ判断の基準**：単一組織・少人数運用。**マルチテナント（顧客分離）は対象外**とする（下記スコープ参照）。

## 3. 解決する課題と提供価値

| 課題 | 提供価値（どう解決するか） |
|---|---|
| 8 プロセスの個別運用が煩雑 | 単一アプリに統合し、起動・管理を一本化 |
| 認証方式がサービスごとにバラバラ | 統一ログイン（ローカル/SSO）＋統一 RBAC で単一のアクセス制御 |
| 画面・操作がサービスごとに不統一 | 標準 UI キット・標準操作パターンで UX を統一 |
| ユーザ/監査/アラート/バックアップ等の重複 | 横断共通機能として一元提供し、各ドメインは固有機能に集中 |
| 全体の稼働状況が俯瞰しづらい | 統合ダッシュボードで全ドメインを一望 |

## 4. スコープ

### 対象（やること）

- 8 ドメイン（DNS / DHCP / LDAP / Mail / Proxy / コンテナ・K8s / SSO / 監視）の管理機能を単一アプリで提供。
- 統一認証（ローカルアカウント＋SSO/OIDC）と統一 RBAC。
- 横断共通機能：統合ダッシュボード、横断監査ログ、横断アラート＆通知、横断バックアップ/リストア、横断テンプレート、統合ログ閲覧、アプリ設定。
- 標準 UI/UX（共通レイアウト・データテーブル・フォーム・確認ダイアログ・トースト・バッジ）と ja/en の i18n、ダーク/ライトテーマ。

### 対象外（やらないこと）

- **マルチテナント（顧客分離）**：単一組織前提。SSO ドメインの「テナント」概念は単一（暗黙）テナントに縮退する（詳細は Phase 4 で確定）。
- **API ゲートウェイ / プロセスマネージャ / サービス別プロセス**：統合により廃止。
- 各サービス個別の認証方式（JWT/セッション/API キー）：統一認証へ吸収し廃止。
- 現行にない新規インフラ種別の追加（本移行では既存 8 ドメインの範囲に限定）。

## 5. 機能一覧

### 5.1 横断共通機能（再設計で第一級に格上げ）

| ID | 機能名 | 概要 | 優先度 |
|---|---|---|---|
| F-01 | 統一認証 | ローカルアカウント＋SSO(OIDC/PKCE) ログイン、初回セットアップ、ログアウト | 高 |
| F-02 | 統一 RBAC | Viewer / Operator / Admin の 3 段ロールで全機能を認可 | 高 |
| F-03 | 統合ダッシュボード | 全 8 ドメインの稼働状況・主要指標サマリ（自動更新） | 高 |
| F-04 | 横断監査ログ | 全ドメインの操作履歴を統一形式で記録・閲覧（日時/実行者/操作/対象/IP/詳細） | 高 |
| F-05 | 横断アラート＆通知 | アラートルール・状態(open/ack/resolved)・重大度・通知（Webhook 等）を横断管理 | 中 |
| F-06 | 横断バックアップ/リストア | 対応ドメインの構成バックアップ作成・一覧・リストア（Admin 限定） | 中 |
| F-07 | 横断テンプレート | 定型設定の登録・再利用・一括適用（対応ドメイン） | 中 |
| F-08 | 統合ログ閲覧 | 各ドメインの動作ログ/クエリログ/アクセスログの統一ビューア | 中 |
| F-09 | アプリ設定 | 言語・テーマ・接続/システム設定、設定ホットリロード | 中 |
| F-10 | アカウント/セッション管理 | ローカルアカウントの CRUD、アクティブセッション一覧・失効 | 高 |

### 5.2 ドメイン管理機能

| ID | 機能名 | 概要 | 優先度 |
|---|---|---|---|
| F-11 | DNS 管理 | ゾーン/レコード CRUD、テンプレート、RPZ、クエリログ/テスト、バックアップ | 高 |
| F-12 | DHCP 管理 | プール/予約 CRUD、リース閲覧・解放、設定、監査 | 高 |
| F-13 | ディレクトリ(LDAP) 管理 | ユーザ/グループ/OU/エントリ CRUD、ツリー閲覧、スキーマ、ACL、LDIF 入出力、変更履歴 | 高 |
| F-14 | Mail 管理 | メールユーザ/ドメイン/エイリアス/メーリングリスト CRUD、プロトコル/サーバ設定 | 高 |
| F-15 | Proxy 管理 | 仮想ホスト/証明書/ACL ルール/IP ブロック/Webhook、アクセスログ、ヘルス | 高 |
| F-16 | コンテナ/K8s 管理 | ホスト/クラスタ/アラートルール/バックアップ/テンプレート管理 | 高 |
| F-17 | SSO/認証プロバイダ管理 | SSO プロバイダ/クライアント/セッション管理（統一認証基盤の管理面） | 中 |
| F-18 | 監視(Watch) 管理 | 監視ホスト/アラート/監視ルール/グループ/メンテナンス、メトリクス | 高 |

> **設計確定（2026-07-05）**：**ログイン識別とドメインユーザを分離**する。Magnetite への*ログイン*は「ローカル＋SSO」の統一認証（F-01/F-10）で一本化する一方、F-13(LDAP)・F-14(Mail)・F-17(SSO)・F-18(監視) 等が扱う*ユーザ/グループ*は各ドメイン固有の管理データとして独立に保つ（ログイン識別 ≠ LDAP エントリ ≠ メールアカウント）。統一するのは **RBAC・横断監査・UI/UX・ログイン体験** であり、ドメインのユーザ実体は統合しない。両者の任意リンク（例：LDAP エントリを SSO ログインの裏付けにする等）の要否は Phase 4 で扱う。

## 6. 用語定義

| 用語 | 定義 |
|---|---|
| ドメイン | 統合対象の 1 サービス領域（DNS/DHCP/…/監視）。旧「サービス」に相当するが、独立プロセスではなくアプリ内部モジュール。 |
| 横断共通機能 | 特定ドメインに属さず、全ドメインで共有する機能（認証/監査/アラート/バックアップ等）。 |
| RBAC | ロールベースアクセス制御。Viewer/Operator/Admin の 3 段。 |
| SSO | OIDC/PKCE によるシングルサインオン。ログイン経路の 1 つ、かつ管理対象ドメインの 1 つ。 |
| 統一 ID 基盤 | （検討中）ユーザ/グループを一元管理する共通の識別基盤の呼称。 |

## 7. 制約・前提条件

- 実装は Rust / Leptos 0.8（SSR+WASM hydrate）/ Axum 0.8 を基本とする（移行元踏襲。詳細は実装フェーズ）。
- 単一組織・単一デプロイ前提（マルチテナント非対象）。
- ja/en の 2 言語、ダーク/ライトテーマに対応。
- ブラウザからサービス認証トークンを露出させない（SSR + サーバ側処理を継続）。

## 8. 成功指標（任意）

- 8 ドメインの主要操作が、単一ログイン後に画面遷移のみで到達できる（再ログイン不要）。
- 共通操作（一覧/作成/削除/確認）が全ドメインで同一の UI パターンで完了できる。
- 全更新操作が横断監査ログに記録される（記録率 100%）。
